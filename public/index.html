    From evidence to evaluation

    How Action E2E works

    E2P turns evidence from a web project into reviewable user journeys, executable tests, and visual results. You stay in control before anything is generated or run.

    Where the model participates

    A selected AI model interprets collected evidence, proposes meaningful flows, drafts acceptance criteria, authors or grounds executable tests, and explains results. If the model cannot complete a required stage, the run stops and reports that failure instead of substituting another strategy.

    Model responsibilities

    How the model participates

    The model drives semantic decisions while E2P supplies evidence, a safe action protocol, human review, and measurable browser execution.

    1. 1
      Select a project

      Point E2P to a local web project you want to study.

    2. 2
      Build project context

      E2P reads documentation and source signals, then can launch the app to observe its rendered interface.

    3. 3
      Confirm access

      Choose a guest session or a protected, read-only authenticated view.

    4. 4
      Explore and challenge the interface

      The selected model chooses constrained UI actions. E2P records resulting states, screenshots, and browser errors, then separates potential defects into observed facts and inferred expectations.

    5. 5
      Review the criteria

      Edit, approve, or reject the expected behavior before test generation.

    6. 6
      Generate E2E tests

      Approved criteria become isolated Playwright artifacts without changing the analyzed project.

    7. 7
      Run the experiment

      E2P starts the target when needed and executes the generated browser journeys.

    8. 8
      Evaluate the outcome

      Use results, screenshots, videos, traces, and limitations to assess both the application and the model-assisted pipeline.
